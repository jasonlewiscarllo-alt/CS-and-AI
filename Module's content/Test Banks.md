## How to use this Test Bank

**Ready for an exam paper.** Every question stands on its own: it gives all the facts and numbers it needs and does not refer to the Study Guide's characters, Missions, figures or tools. A teacher can copy any question straight into a quiz or a final exam, and pick questions by topic, section or skill using the tables below.

**Try before you look.** Part 1 contains only questions. Part 2, the Answer Key, starts on a new page after all the questions. Write your own answer first, then check the key and read the explanation: each one says *why* the right answer is right and, for multiple choice, why each tempting wrong answer fails. In the key, every question number is a link back to its question.

**Tags.** Every question has a tag such as **[HW · 1.5 · Apply]**: the topic (HW = Hardware, NW = Networks, AI = Behaviourist AI), the Study Guide section it tests, and the skill: **Recall** (remember a fact or definition), **Apply** (use an idea in a new case or a calculation) or **Analyse** (compare, explain, evaluate or find a fault). Most questions are Apply or Analyse; recall questions are kept for the definitions every learner must know.

| Type | HW | NW | AI | Mixed | Total | Recall | Apply | Analyse | Instruction |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| True / False | 13 | 13 | 14 | – | 40 | 11 | 14 | 15 | Write T or F. For every F, correct the statement. |
| Multiple choice | 13 | 13 | 14 | – | 40 | 2 | 18 | 20 | Choose one answer. |
| Open-ended | 4 | 3 | 5 | 1 | 13 | 0 | 7 | 6 | A developed answer, normally 150–300 words, or equivalent worked steps, tables or diagrams. 8 marks each. |
| **All** | **30** | **29** | **33** | **1** | **93** | **13** | **39** | **41** |  |

**Suggested timing.** Section A: 30 minutes. Section B: 60 minutes. Each open-ended question: about 12 minutes (question 93: 20 minutes). A calculator is allowed. Where a question needs a unit convention it states it, for example 1 MB = 1 000 000 bytes.

**Marking.** True/false: 1 mark each (a correct F needs a valid correction for the mark). Multiple choice: 1 mark each. Open-ended: 8 marks each, using the marking points in Part 2. Total: 40 + 40 + 104 = 184 marks.

**Making a shorter paper.** For a one-hour test, take 10 true/false, 10 multiple-choice and 3 open-ended questions, choosing at least one of each from HW, NW and AI; the coverage map in the appendix shows which questions test each section.

### Section C · Open-ended: marking points and model answers

#### [81.](#q81) The fetch–decode–execute cycle and interrupts (8 marks)

**Marking points (1 mark each, up to 8):** the PC holds the address of the next instruction; it is copied to the MAR; the address travels on the address bus and a READ signal on the control bus; the instruction comes back on the data bus into the MDR; it is copied to the CIR; the PC is increased by one; the CU decodes the opcode and operand; the ALU executes and flags in the SR are set; the result is written back to the ACC or memory; interrupts are checked at the end of each cycle; the state is saved, the ISR runs (highest priority first) and the state is restored, so the program continues.

**Model answer.** The Program Counter holds the address of the next instruction. In the fetch, that address is copied to the MAR and sent along the address bus, while the Control Unit sends a READ signal on the control bus. Memory returns the instruction along the data bus into the MDR, and it is copied to the CIR; the PC is then increased so it points to the next instruction. In the decode step the CU splits the instruction into an opcode (what to do) and an operand (the data or its address) and sets up the control signals. In the execute step the ALU calculates (or data moves between memory and a register) and the status flags are updated. The result is written back to the accumulator or to memory, and the cycle repeats. At the end of each cycle the processor checks for interrupts. If one has arrived, it saves its registers, runs the interrupt service routine for the highest-priority interrupt, restores the registers and carries on exactly where it stopped: the program is paused, not restarted.

#### [82.](#q82) DRAM, SRAM and the memory hierarchy (8 marks)

**Marking points:** DRAM stores a bit with one transistor and one capacitor; it needs refreshing because the charge leaks; SRAM uses about six transistors per bit and needs no refresh; SRAM is much faster; DRAM is denser and cheaper per bit; both are volatile; DRAM is used for main memory and SRAM for cache; the hierarchy exists because fast memory is expensive and small; locality makes a small fast cache effective; any correct tier example (registers, cache, RAM, SSD) with a size or speed.

**Model answer.** DRAM stores each bit as charge on a tiny capacitor controlled by one transistor. The charge leaks, so DRAM must be refreshed thousands of times a second; it is slower but dense and cheap, which makes it ideal for main memory (gigabytes). SRAM stores each bit in a circuit of about six transistors that holds its value while powered, so it needs no refresh and is much faster, but it takes more space and costs more per bit, so it is used for the CPU's caches (kilobytes to megabytes). Both are volatile. Computers use a hierarchy (registers, cache, RAM, SSD) because no single technology is fast, large and cheap at once. Programs show locality: they reuse recently used data and the data next to it, so keeping that small working set in a fast cache means most requests are served quickly, while the bulk of the data sits in cheaper, larger memory below.

#### [83.](#q83) Binary, hexadecimal and the half-adder (8 marks)

**Marking points:** 45 = 32 + 8 + 4 + 1 (or repeated division by 2); 8-bit binary 00101101; split into nibbles 0010 1101; hexadecimal 2D; one hex digit has 16 values and 16 = 2<sup>4</sup>, so it matches exactly four bits; a correct use (memory addresses, machine code, MAC addresses or colour codes); a correct truth table (00 → Sum 0 Carry 0; 01 and 10 → Sum 1 Carry 0; 11 → Sum 0 Carry 1); Sum from XOR and Carry from AND; a full adder also adds a carry in from the column to its right (three inputs), and chains of full adders add multi-bit numbers in the ALU.

**Model answer.** (a) 45 = 32 + 8 + 4 + 1, so the bits for 32, 8, 4 and 1 are set: 101101, or 00101101 as a full byte. Split into nibbles, 0010 = 2 and 1101 = 13 = D, so 45 = 2D in hexadecimal. (b) Four bits have 2<sup>4</sup> = 16 patterns, exactly the 16 digits 0–F, so every hex digit stands for one nibble and a byte is always two hex digits. Hexadecimal is used for memory addresses, machine code, MAC addresses and web colour codes such as #E4572E. (c) A half-adder's truth table: A = 0, B = 0 gives Sum 0, Carry 0; A = 0, B = 1 and A = 1, B = 0 give Sum 1, Carry 0; A = 1, B = 1 gives Sum 0, Carry 1, because 1 + 1 = 10 in binary. Sum comes from an XOR gate and Carry from an AND gate. A half-adder has only two inputs, so it cannot accept the carry from the column to its right. A full adder adds three bits (A, B and a carry in); chaining full adders lets the ALU add whole bytes.

#### [84.](#q84) An embedded greenhouse controller (8 marks)

**Marking points:** a temperature sensor and a soil-moisture sensor; at least two actuators (heater, fan or vent motor, water valve or pump); a microcontroller compares readings with targets in a repeating feedback loop; the ADC sits between each analogue sensor and the microcontroller, because the microcontroller can only process digital numbers; the narrow gap makes the heater switch on and off very often ("chatter") as the temperature wobbles around 18 °C; that wears out the relay or heater; the fix is hysteresis: a gap between the switch-on and switch-off points (for example on below 18 °C, off above 20 °C); soft real-time, because a delay of a few seconds harms no plant, with a hard real-time example such as an airbag or anti-lock brakes.

**Model answer.** (a) The system needs a temperature sensor and a soil-moisture sensor as inputs, and a heater, a vent or fan motor and a water valve as actuators. A microcontroller runs a loop: read the sensors, compare each reading with its target, switch the actuators, repeat. The sensors produce analogue voltages, so an ADC converts each reading into a number before the microcontroller, which works only with digital data, can use it. (b) With only 0.2 °C between the switch points, every small wobble of the temperature around 18 °C crosses one of them, so the heater clicks on and off many times an hour all night. This "chatter" wears out the relay and wastes energy. A better design leaves a gap, called hysteresis, for example heater on below 18 °C and off above 20 °C: the temperature swings a little more, but the heater switches far less often. (c) It is soft real-time: if the heater switches a few seconds late, the plants are not harmed, so a missed deadline only lowers quality. An airbag controller is hard real-time, because a late response is a failure.

#### [85.](#q85) A photo's journey across networks (8 marks)

**Marking points:** data split into packets; header with source, destination and sequence number; payload; trailer or error check; packets routed independently by routers using IP addresses; packets may take different routes and arrive out of order; IP is connectionless and gives no guarantees; TCP numbers, acknowledges, resends lost packets and reorders; a lost packet is detected (missing sequence number or no acknowledgement) and only that packet is resent; more robust because routes avoid failures and only missing pieces are resent.

**Model answer.** The photo is cut into many packets. Each has a header (the laptop's IP address, the server's IP address and a sequence number), a payload (one slice of the photo) and error-checking bits. Routers read the destination IP address and forward each packet towards the server along whatever route is best at that moment, so packets may travel different routes and arrive out of order. IP's job is only addressing and routing; it is connectionless and makes no promise about delivery. TCP, on top of IP, makes the transfer reliable: it sets up a connection, numbers the data, has the receiver acknowledge what arrives, resends anything that is not acknowledged, and puts the packets back in order using the sequence numbers. If one packet is lost, only that packet is resent. This is more robust than one long stream: a broken cable or router only diverts packets around it, and a single loss does not mean starting again.

Two threats: phishing emails that steal staff passwords, countered by training, spam filtering and multi-factor authentication; and ransomware arriving through unpatched software, countered by automatic patching, antivirus and regular offline backups.

#### [87.](#q87) DNS, transfer time and addresses (8 marks)

**Marking points:** URL parts: protocol https, subdomain www, domain name example, top-level domain com, path /news; the device first checks its own cache; it asks a DNS resolver (usually the provider's or the school's); the resolver asks other DNS servers step by step; the IP address comes back and the browser connects to it; 450 × 8 = 3 600 Mbit; 3 600 ÷ 90 = 40 s; file sizes are in bytes but link speeds in bits, a factor of 8; 2<sup>32</sup> = 4 294 967 296 (about 4.3 billion) addresses; not enough for every device in the world, so IPv6 uses 128 bits.

**Model answer.** (a) In https://www.example.com/news, https is the protocol, www the subdomain, example the domain name, com the top-level domain and /news the path to the page. Routers deliver by IP address, so the name must be translated: the device first checks its own cache of recent answers; if the answer is not there, it asks a DNS resolver, usually run by the internet provider or the school; the resolver asks other DNS servers in turn until one gives the IP address; the address comes back to the device and the browser connects to it. (b) 450 MB × 8 = 3 600 Mbit, and 3 600 ÷ 90 = 40 seconds. Dividing 450 by 90 mixes units: the file size is in bytes and the link speed in bits per second, and there are 8 bits in a byte. (c) 32 bits allow 2<sup>32</sup> = 4 294 967 296 addresses, about 4.3 billion. That is fewer than the number of phones, computers and other devices now online, so IPv6 was introduced with 128-bit addresses, enough for every device many times over.

#### [88.](#q88) Why sense–model–plan–act struggled (8 marks)

**Marking points:** the SMPA loop described; the latency bottleneck explained; the calculation 0.6 × 2.5 = 1.5 m driven on an old plan; the reactive distance 0.6 × 0.02 = 0.012 m (1.2 cm); the frame problem explained with an example; the symbol grounding problem explained with an example; "the world is its own best model" answers stale maps and the frame problem; tight sensorimotor coupling answers latency; embodiment and situatedness, or emergent behaviour, linked correctly.

**Model answer.** A classical robot senses, updates a full world model, plans and only then acts. Planning takes time, so the plan is out of date before it starts: at 0.6 m/s, 2.5 s of planning means 0.6 × 2.5 = 1.5 m driven on an old plan, whereas a reactive controller checking 50 times a second moves only 0.6 × 0.02 = 0.012 m (about 1 cm) between checks. The frame problem makes the model itself impossible to keep up to date: after every action the robot must confirm the endless list of things that did not change (the walls, the furniture, the time). The symbol grounding problem means the model's symbols, such as DOOR_OPEN, have no natural link to the camera's pixels or a sensor's echoes. Brooks answered by not keeping such a model: the world is its own best model, so the robot asks its sensors again; tight sensorimotor coupling connects sensors to motors in fast, parallel loops; and useful behaviour emerges from simple rules interacting with the real, embodied world.

#### [89.](#q89) A subsumption lawnmower (8 marks)

**Marking points:** three sensible layers in order (for example Layer 0 stop at obstacles or edges; Layer 1 mow forward in rows; Layer 2 return to the charger or follow a boundary); Layer 0 never silenced, with a reason; a correct example of suppression (a higher layer replacing a lower layer's input, such as a heading); a correct example of inhibition (a higher layer blocking a lower layer's output, such as the blade or the "mow" command); net force (2 − 1, 1 + 0.5) = (1, 1.5); (0, 0) explained as a local minimum; an escape (random push or wall-following).

**Model answer.** Layer 0, Avoid: a bumper or edge sensor stops the wheels and the blade, reverses and turns; it is wired directly to the motors and nothing above can silence it. Layer 1, Mow: drive forward along rows and turn at the end of each row. Layer 2, Return: when the battery is low, steer to the charger. Suppression: Layer 2 replaces Layer 1's heading input with the direction of the charger. Inhibition: while returning, Layer 2 blocks Layer 1's "blade on" output so the robot does not mow on the way home. Navigation: net = (2 − 1, 1 + 0.5) = (1, 1.5). If the net force became (0, 0) before the goal, the robot would be in a local minimum; it should add a small random push for a few steps or follow the obstacle's edge until the pull points the way again.

#### [90.](#q90) A pedestrian crossing as a state machine (8 marks)

**Marking points:** three states named (GREEN, AMBER, RED); row GREEN + button pressed → AMBER; row AMBER + 3-second timer ends → RED; row RED + 20-second timer ends → GREEN; trace AMBER, RED, RED, GREEN, GREEN; 3 transitions, with the two events that change nothing identified; pressing the button in RED has no row, so nothing happens, which is acceptable because the light is already red (or: a sensible design note, such as remembering the press for the next cycle); one advantage (exactly one state at a time, easy to test every row, predictable and safe) and one limitation (only handles the triggers someone thought of, such as no emergency-vehicle mode; tables grow quickly with more states).

**Model answer.** (a) States: GREEN, AMBER and RED. Rows: GREEN, button pressed → AMBER; AMBER, 3-second timer ends → RED; RED, 20-second timer ends → GREEN. (b) Button pressed: GREEN → AMBER. 3-second timer ends: AMBER → RED. Button pressed: there is no row for RED, so it stays RED. 20-second timer ends: RED → GREEN. 3-second timer ends: no row for GREEN, so it stays GREEN. The states are AMBER, RED, RED, GREEN, GREEN, and there are 3 transitions. (c) The table has no row for a press in RED, so nothing happens. That is acceptable, because pedestrians can already cross; a designer might still add a "request waiting" note so that a press during AMBER or RED is not forgotten. (d) Advantage: a crossing must always be in exactly one, known state, and every row can be tested, which matters for safety. Limitation: the machine only reacts to the triggers in its table, so situations nobody listed, such as an ambulance approaching or a stuck button, need new states and rows.

#### [91.](#q91) Q-learning and SARSA (8 marks)

**Marking points:** Q-learning target 0 + 0.9 × max(1, 0) = 0.9; TD error 0.4; new Q 0.54; SARSA target 0 + 0.9 × 0 = 0; TD error −0.5; new Q 0.45; Q-learning assumes the best next action (off-policy), SARSA uses the action actually taken (on-policy); beside the cliff, Q-learning learns the shortest path along the edge (13 steps in the standard 4 × 12 cliff-walk) and SARSA a longer, safer path; choose SARSA (or a safer design) for a robot that keeps exploring, with a reason.

**Model answer.** (a) Q-learning: target = 0 + 0.9 × max(1, 0) = 0.9; TD error = 0.9 − 0.5 = 0.4; new Q = 0.5 + 0.1 × 0.4 = 0.54. SARSA uses the action actually taken (Up, worth 0): target = 0 + 0.9 × 0 = 0; TD error = −0.5; new Q = 0.5 + 0.1 × (−0.5) = 0.45. (b) Q-learning updates as if the next action will be the best one, so it values cells beside the cliff as safe and learns the shortest path along the edge (13 steps in Sutton and Barto's 4 × 12 cliff-walk), but while it still explores, about one move in ten is random and a random step into the cliff costs −100. SARSA includes those exploratory steps in its targets, so it learns that edge cells are risky for an exploring agent and takes a longer path further away. For a real robot that keeps exploring, SARSA is the safer choice, together with physical safeguards that do not depend on learning.

#### [92.](#q92) Reward hacking and ethics (8 marks)

**Marking points:** a plausible hack (driving around without delivering to collect +1 per minute; taking long routes; splitting one delivery into many); a fix (remove the time reward or make it a small penalty; reward each delivery once, only when confirmed; a penalty for lateness); two ethical issues explained (privacy of patients and staff filmed in corridors; consent; data storage; responsibility if harm occurs); a safeguard for each (process on board, blur faces, keep no video, short retention, signs, access controls, a named responsible person).

**Model answer.** (a) Because it earns +1 for every minute it is moving, the robot can earn more by wandering the corridors than by delivering quickly, for example taking the longest route each time. Fix: remove the moving reward (or make time a small penalty), give +10 only when a delivery is confirmed, and add a penalty for lateness. (b) Privacy: corridor cameras can record patients at vulnerable moments. Safeguard: recognise obstacles on board and never store or send video; blur faces if anything must be kept. Consent: patients and visitors cannot easily opt out of being filmed. Safeguard: clear signs, collecting only the minimum data, and an easy way to ask for data to be deleted. (Responsibility, with a named person accountable for incidents, is also a good answer.)

#### [93.](#q93) Integrated question: the delivery robot (8 marks)

**Marking points:** (a) CPU for the operating system and job logic (low latency); GPU or NPU for neural networks and navigation maths (throughput); (b) 150 × 20 = 3 000 bytes per second = 24 000 bits per second; telemetry by UDP because a lost update is replaced by the next; targets by TCP because they must arrive complete and correct; (c) network latency (tens of milliseconds or more) and unreliability (lost packets, dropped signal); a pedestrian can step out faster than a round trip; the lowest layer gives tight sensor–motor coupling and cannot be silenced by remote commands.

**Model answer.** (a) The CPU runs the operating system and the job logic, which are sequential and need low latency; the GPU and the NPU run the neural networks that recognise people in images and the navigation maths, which need high throughput. (b) 150 × 20 = 3 000 bytes per second, which is 24 000 bits per second (24 kbit/s). Telemetry should use UDP: it is sent many times a second, so a lost update is simply replaced by the next and resending it would only add delay. Delivery targets should use TCP, because a wrong or partial address is useless. (c) A message to the server and back takes tens of milliseconds and can be lost or delayed if the signal drops, but a pedestrian can step in front of the robot faster than that. As the lowest subsumption layer on board, the emergency stop links the proximity sensors directly to the motors, reacts within milliseconds and cannot be overridden by any remote command.
