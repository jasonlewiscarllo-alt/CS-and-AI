## 3 Target Learners and Learning Goals

### Assumed Background Knowledge

Learners need no prior knowledge of computing. Binary and denary are taught in the Hardware topic (Topic 1), so learners do not need to study them beforehand. At most, they may know that computers use 0s and 1s. Topic 1 builds binary and denary step by step from place value, before it moves on to hardware components, so later topics can use them.

### Learning Goals

After using the module materials, beginners will be able to:

> The first four goals below are taught in Topic 1 (Hardware fundamentals, binary and denary).

- Explain what a bit is and why computers use binary (two states, stored as 1 and 0).
- Explain place value in denary (base 10) and in binary (base 2), and say what each binary place is worth (1, 2, 4, 8, 16, 32, 64, 128).
- Convert binary numbers of up to 8 bits to denary, and denary numbers from 0 to 255 to binary, showing the working.
- State how many different values a number of bits can store (for example 8 bits store 256 values, 0 to 255) and check a conversion by converting back.
- Name the main hardware components and explain what each one is used for.
- Explain the different types of RAM and ROM and compare them (for example SRAM and DRAM; PROM, EPROM and EEPROM).
- Name the main network components and state the purpose of each.
- Describe four network topologies and list two advantages and two disadvantages of each; choose a suitable topology for a simple scenario.
- State the purpose of every network protocol listed in the course materials and match each protocol to a use (the final list is taken from the course materials in Task 2.1b).
- Identify common network threats and explain basic defences against them.
- Explain in simple words what behavioural AI is, and name its two common meanings: AI built from simple behaviours that senses and acts, and AI that analyses and predicts human behaviour.
- Describe the sense-decide-act loop using an everyday example, such as a robot vacuum or a game guard.
- Draw a simple finite state machine (three or four states with labelled transitions) for a game character such as a guard.
- Explain how data about behaviour (clicks, purchases, log-ins) can be used to make recommendations or spot unusual activity, and link this to the network security topic.
- Give one benefit and one risk of behavioural AI (for example fewer fraud losses against false alarms and privacy concerns).

### Beginner questions: binary and denary (Topic 1: Hardware)

- What is a bit, and why do computers use only 0s and 1s?
- What is each place in a binary number worth?
- How do I turn 1011 0110 into denary, and 150 into binary?
- How many different values can 8 bits store?
- How can I check that my conversion is right?

### Beginner questions: Behavioural AI (Topic 5)

- What does 'behavioural' mean when we talk about AI?
- How does an AI sense what is happening, decide, and then act?
- What is a state, and what makes a game character change from one state to another?
- How can a bank or a website tell that an account is behaving unusually?
- Why might behavioural AI get it wrong, and who could be affected?

## 5 Planned Learning Resources and Mini Lecture

### Shared Markdown Content (`content/`)

The single source of truth for every other resource. One modular `.md` file per topic, kept in `content/`, with diagrams in `assets/`, review and project records in `docs/`, and the Study Guide, slides and videos in their own folders. Each topic file uses the same order: learning objectives, key terms (explicit definitions), beginner explanation, worked example, visual reference, learner exercises, answer key, and references. Each file carries a status label (`[Outline Only]`, `[Drafted]`, `[Checked]`). Binary and denary are part of the Topic 1 (Hardware) file. They are not a separate file, so every resource draws on the same Topic 1 content.

### Study Guide and Test Bank

| Part | Plan |
|---|---|
| **Structure** | A study booklet compiled from the Markdown chapters: objectives, explanations, key terms, worked examples (including place-value tables for binary and denary, taught in the Hardware chapter), chapter summary. First version in Stage 2 (Task 2.15); final version in Stage 3 (Task 3.1). |
| **How learners study** | Read a chapter, answer its self-check questions, then attempt the test bank for that topic. |
| **Practice and checking** | Self-check concept questions after each chapter; a test bank mixing recall, explain and apply questions mapped to the learning goals, including binary and denary conversion sets graded from 4-bit to 8-bit numbers; a separate answer file so learners can check whether they have really understood. |

### PPT Slides

Slides turn the `[Checked]` Markdown into visual explanations. In the Hardware section, a binary place-value table fills in step by step as 1011 0110 is converted to denary (182) and 150 is converted to binary (1001 0110), followed by a RAM versus ROM comparison diagram, a network components diagram, one diagram per topology, and a step-by-step animated worked example showing a message travelling across a star network, plus a state-machine diagram of a game guard for Behavioural AI. Slides use concise bullet points with full speaker notes. A separate short deck supports the mini lecture (Task 2.12).

Script in Task 2.13, first draft in Task 2.14. |

### How the Three Resources Support One Another

The Markdown files are the foundation. The Study Guide compiles them for reading and practice; the slides turn the same explanations and diagrams into visuals; the videos narrate the slide animations for the hardest processes. Test-bank questions map to the same learning goals, so a learner can read, watch, then self-test on the same ideas. Any correction is made in Markdown first and then carried to every deliverable (Section 6).

### Live Mini Lecture

- **Topic:** Network Threats and Network Security (the team's decided topic)
- **Focus question:** How can one phishing email put a whole network at risk, and which simple defences stop it?
- **Why it matters:** Every learner uses networks daily. Threats are common and many are stopped by habits and basic tools, so the topic is both practical and linked to network components and protocols in the module.
- **Example / demo:** Trace one phishing email step by step: delivery, click, spread, and the point where a firewall, update or careful user stops it.
- **Audience activity:** Show four short sample emails (written by the team, Task 2.3a). The audience votes which are phishing, then the team reveals the warning signs.
- **Roles:** Kelton (public speaking) leads and presents, supported by Kenzo in preparation (Task 2.3a); mini-lecture slides by Louis (Task 2.12); Louis leads the collection of audience feedback (Task 2.17)
